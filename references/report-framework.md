## 1. 核心分析链路

### 1. 表面信号

写清业务现在看到了什么，例如活跃峰值、高价率上升、转化下降、活动流水增长。避免把指标直接等同于业务事实。

### 2. 误读风险

指出指标可能混合的成分：

- 不同用户层级；
- 不同生命周期阶段；
- 外部冲击和内部动作；
- 真实业务变化和数据质量问题；
- 短期峰值和长期承接；
- 总量变化和结构变化。

如果证据不支持“指标失真”，使用“需补充以下限定”而不是制造反常识结论。

### 3. 口径重建

在展示结果之前写清：

- 观察单位；
- 样本进入和排除规则；
- 分子、分母和聚合层级；
- 时间窗口与对齐时点；
- 互斥分层还是累计分层；
- 实际价格、系统快照或其他不同数据状态；
- 可比较范围。

### 4. 结构拆解

优先选择能解释总体结果的维度：

- 人群：新进、回流、留存、浅层、深层、高价值；
- 时间：活动前、活动中、活动后，或生命周期阶段；
- 来源：自然、投放、产品机制、运营动作、外部市场；
- 机制：覆盖、触发、响应、充分度、关闭；
- 责任：产品、运营、数据、技术、渠道；
- 数据质量：准确性、时效性、完整性、匹配性。

避免同时铺开太多维度。主文只保留能改变决策的拆解。

### 5. 比较验证

每条重要判断应基于明确比较：

- 同期不同组；
- 同组前后；
- 处理与对照；
- 系统值与同口径校准值；
- 总体与分层；
- 绝对变化与贡献份额。

不能建立有效比较时，将结果标为描述性观察。

### 6. 业务转译

把“数值不同”转成以下至少一类含义：

- 谁形成了结果；
- 哪个阶段发生分化；
- 哪种机制发挥或未发挥作用；
- 哪个群体/类目应优先处理；
- 哪项结论会改变当前判断。

### 7. 行动闭环

建议写成：

```text
发现 → 动作 → 承接方 → 优先级 → 验证指标 → 复盘时间
```

避免“持续关注、进一步优化、加强协同”等无承接动作。

### 8. 边界披露

必须靠近结论披露：

- 样本覆盖和代表性；
- 数据缺失及异常；
- 相关或因果；
- 外推范围；
- 仿真或脱敏；
- 四舍五入；
- 未控制的机制。

## 2. 报告规格

`report-spec.md` 建议使用以下格式：

```markdown
# 报告规格

## 受众与决策
- 受众：
- 需要支持的决策：
- 阅读时间目标：

## 核心命题
- 表面信号：
- 误读风险：
- 核心命题：

## 观察口径
- 单位：
- 样本：
- 时间：
- 分子/分母：
- 比较基准：

## 首屏 KPI
| KPI | 数值 | 证据 ID | 口径 | 边界 |

## 章节和组件
| 章节 | 回答的问题 | 证据 | 组件 | 结论 |

## 行动
| 发现 | 动作 | Owner | 优先级 | 验证指标 |

## 待确认项
```

## 3. 默认章节结构

### 01 核心结论

用 3—5 张结论卡回答：发生了什么、为什么重要、适用范围是什么。

### 02 决策建议

把建议放在方法之前。管理者应能在首屏或前两屏读到。

### 03 业务问题与指标误读

用 `WHY → SO WHAT → NOW WHAT` 或“背景—冲突—重建”说明为何需要新框架。

### 04 观察对象与分析框架

展示样本、单位、分层及数据路径。

### 05 关键拆解

用最少图表证明结论。一个模块回答一个问题。

### 06 方法与诊断

提供比较设计、统计诊断、数据校准和详细口径。对管理层可折叠，对分析评审不可省略。

### 07 业务行动

按 Owner 或行动链路组织，不按图表顺序重复结论。

### 08 局限与后续验证

明确未解决问题、验证指标和下一复盘窗口。

## 4. 双层阅读设计

### 快速路径

```text
标题 → 核心命题 → KPI → 建议 → Owner
```

目标：无需读模型细节也能做方向判断。

### 复核路径

```text
观察口径 → 拆解证据 → 方法 → 明细 → 边界
```

目标：分析师能够复核结论来源和适用条件。

通过字号、卡片、颜色和折叠区分层，不通过删除方法实现“简洁”。

## 5. 何时停止并追问

出现以下情况时，不得生成确定性结论：

- 核心数字没有来源；
- 分母、时间窗口或观察单位不清；
- 两份材料对同一数字冲突；
- 用户要求因果结论但只提供相关数据；
- 行动建议需要公司内部规则而材料未提供；
- 无法判断输出是内部版还是公开版；
- 输入含敏感明细但没有处理授权。
