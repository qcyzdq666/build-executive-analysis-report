# 管理层报告组件目录

## 目录

1. 选择原则
2. 首屏组件
3. 解释组件
4. 证据组件
5. 行动与边界组件
6. 禁止用法

## 1. 选择原则

每个组件必须回答一个问题。先写“这个模块要让读者做出什么判断”，再选择形式。

优先级：

1. 结论是否清楚；
2. 比较是否正确；
3. 口径是否可见；
4. 图形是否必要；
5. 页面是否美观。

管理层主文建议控制在 3—7 个核心可视化，详细结果进入表格或折叠区。

## 2. 首屏组件

### Hero

适合：主题、核心命题、时间范围和披露。

必须包含：

- 业务主题；
- 一句话核心命题；
- 观察时间或版本；
- 内部/脱敏/仿真声明（如适用）。

### KPI 卡片

适合：3—5 个能改变判断的数字。

每张卡包括：

- 对象或口径标签；
- 数值或结论；
- 一句话解释；
- 样本或适用范围。

不要把普通描述性统计全部做成 KPI。

### 决策建议条

适合：报告读完后需要批准或推动的 1—3 项动作。

写明动作、Owner 和验证指标。不要只写“建议关注”。

## 3. 解释组件

### WHY—SO WHAT—NOW WHAT

适合：解释现有指标为何不能直接支持决策，以及新框架如何解决。

### 背景—冲突—问题卡

适合：复杂专项的三问结构，例如观察谁、贡献多少、哪个阶段最好。

### 时间线

适合：活动窗口、版本阶段、动作先后和 T/T+1 链路。

禁止：只有日期没有分析含义。

### 分析架构/流程图

适合：数据层、校准层、验证层，或“信号—分流—动作—关闭”。

节点控制在 3—7 个，每个节点说明输入或产出。

## 4. 证据组件

### 分组卡片

适合：三到四个互斥群体的经营角色比较。

需要同时写样本占比和结果贡献，避免把规模大误当作效率高。

### 漏斗图

适合：互斥阶段转化、累计分层或治理链路。

必须说明漏斗是累计还是互斥，以及每层分母。

### 趋势图

适合：同口径随时间变化。

需要标出版本、活动或制度变更点。不同时间口径不一致时不得直接连线。

### 贡献/堆叠图

适合：总体由哪些互斥部分构成。

各部分必须使用同一分母；如总和不为 100%，解释重叠或其他项。

### 瀑布或桥接图

适合：从系统值到校准值、从基线到结果的分步变化。

不能把相关项机械相加为因果贡献。

### 热力图

适合：赛季 × 玩家层、类目 × 指标等二维结构比较。

必须给出颜色含义和同维度可比性。

### 对比表

适合：样本不足、精确数值、处理规则或多维信息。

数据复杂时表格优于拥挤图表。

### 方法诊断

适合：匹配平衡性、前趋势、置信区间、覆盖率、准确率。

放在结论之后，但因诊断失败会推翻结论时必须前置风险。

## 5. 行动与边界组件

### Owner 行动卡

结构：

```text
Owner → 当前问题 → 具体动作 → 优先对象 → 验证指标
```

### 告警分流

适合：同一异常需要流向不同团队。先剔除不可执行和数据问题，再计算业务执行漏斗。

### 口径折叠区

适合：计算规则、明细表、公式和评分权重。

不能把改变主结论的重要边界只放在折叠区。

### 披露/边界提示

适合：仿真、脱敏、样本、外推、相关/因果和四舍五入说明。

位置必须靠近受影响结论。

## 6. 禁止用法

- 用饼图展示十几个类别；
- 用面积或 3D 效果夸大变化；
- 只显示百分比而隐藏样本量；
- 把互相重叠的人群堆叠成 100%；
- 用颜色表达好坏但没有阈值；
- 让图表标题只描述形式，如“柱状图分析”；
- 在 Tooltip 中嵌入不应分发的原始明细；
- 图表与附近结论使用不同分母；
- 为了页面丰富重复展示同一数字。
