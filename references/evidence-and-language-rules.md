## 1. 证据映射

每条核心结论至少对应一项可定位证据。

优先级：

1. 用户提供的聚合数据或分析结果；
2. 用户确认的现有报告；
3. 明确标注的仿真数据；
4. 已说明来源的外部公开材料。

不得把模型推断写成“数据表明”。如果结论包含多步推导，在 `metric_definition` 中记录公式或推导路径。

建议使用：

```text
claim_id: C01
evidence_id: E03
claim: 核心玩家承接主要现金流水
source: season_tier_summary.csv!revenue_share
metric_definition: 该层玩家现金流水 / 该赛季全量现金流水
scope: 指定赛季和进入观察池的账号—赛季
causal_status: descriptive
```

## 2. 数值写法

### 百分比和百分点

- 比例由 20% 变为 25%：上升 5 个百分点（5pp）。
- 相对增幅：(25%-20%)/20%=25%。
- 除非业务习惯明确，正文同时给出起点、终点和变化值。

### 分子与分母

至少首次出现时说明分母。以下不能混为同一口径：

- 全量用户 vs 观察池用户；
- SKU vs SKU—日；
- 系统判高样本 vs 全部样本；
- 商家报价 vs 平台 SKU 最低有效价；
- 去重账号 vs 账号—赛季。

### 四舍五入

派生数值优先使用未四舍五入原值计算。因展示产生 0.01pp 等差异时加注说明。

### 样本不足

低于业务或统计展示门槛时：

- 显示样本量；
- 标记“样本不足”；
- 不给出精确排序或确定性单点判断；
- 不通过视觉颜色制造强弱结论。

## 3. 相关与因果

### 描述性

可用：

- 占比为；
- 观察到；
- 主要集中于；
- 同期变化；
- 在该样本中更高/更低。

### 关联性

可用：

- 与……相关；
- 可关联至；
- 时间上先于；
- 与……同时出现；
- 可能受到……影响。

### 准因果或因果

只有输入提供并通过适当识别、诊断和范围说明时，才能使用：

- 局部处理效果；
- 相对对照组减少；
- 在共同支撑范围内的 ATT；
- 导致、驱动、提升、贡献。

即使存在 DID、PSM-DID、实验或其他设计，也必须写清：

- 处理定义；
- 对照定义；
- 识别假设；
- 诊断结果；
- 估计对象和适用范围。

### 高风险词

校验器会提示但不会自动判错：

```text
导致、驱动、促进、提升、贡献、证明、决定、归因于、带来
```

人工需要确认这些词是否与证据等级匹配。

## 4. 样本与外推

报告必须区分：

- 经营重点样本：适合定位主要业务风险；
- 概率样本：可在设计允许时估计总体；
- 匹配样本：只解释共同支撑范围内对象；
- 人工核验样本：适合校准系统准确性，外推需额外依据；
- 仿真数据：只用于展示方法，不代表公司指标。

禁止表述：

> 400 个重点 SKU 中错杀 17%，所以全平台告警有 17% 都是错杀。

除非用户提供了代表性抽样和外推权重依据。

## 5. 数据安全

### 内部版

- 仍需遵守公司允许的数据和模型渠道；
- 单文件 HTML 源码中的 JavaScript 数据同样属于报告内容；
- 不因页面未展示就默认源数据安全；
- 原始行级数据只在明确必要且获授权时嵌入。

### 公开或求职版

- 公司、渠道和产品名按要求脱敏；
- 使用聚合、脱敏或仿真数据；
- 删除账号、SKU、商家、链接、手机号、邮箱等可识别明细；
- 删除 HTML 注释、脚本常量和调试信息中的敏感内容；
- 不加载外部分析脚本、像素、字体或 CDN；
- 明示哪些是真实业务框架，哪些是仿真数值。

### 不确定时

将输出默认视作“未获公开授权”，先生成本地草稿并标记需人工脱敏审查。

## 6. 发布前语言检查

逐条检查：

- 主标题是否超出证据；
- KPI 是否写清口径和范围；
- “主要”“核心”“显著”等强词是否有比较依据；
- 建议是否由证据推导，而非通用套话；
- Owner 是否来自用户材料或用户确认；
- 局限是否放在会改变读者判断的位置；
- 报告是否暗示做过未实际执行的分析、测试或验证；
- 是否声称提高效率、触达或采用率但没有前后数据。
